"I need to add a comprehensive 'Quote Database' feature to this app, accessible through the ‘Team’ page. I currently have a database of several thousand full-text news stories, and new ones are continuously added by users and bots.  I want to turn that information into a Quote Database.  In addition, to help facilitate, when a user submits a story to the ‘Team Page’ with ‘Review On’, when the app scrapes the hyperlink, it should fill in the ‘Generate Bullets from Article Text’ box with the actual news article.  If the story fails to scrape, the user must copy the text of the story into that box in order to ‘save and submit’.
Please build the following full-stack feature:
1. Database Schema & Linkage: Create a new Quotes table. It needs the following columns: Quote Text, Speaker Name, Normalized Speaker Name, Location, Subject Tags (array of strings), Article Context (1-sentence summary), Source Reference URL, Date Spoken/Published, and a story_id column. The story_id must act as a foreign key that references the unique primary key of the original article in my existing Stories database.
2. AI Extraction Logic & System Prompt: Write a utility function using an LLM API (e.g., OpenAI or Google AI) that takes the text of a news story as input and outputs a structured JSON array of all quotes found within it.
Crucially, you must use the following EXACT system prompt for the LLM call to ensure the data is formatted correctly for the database: 'You are an expert data extraction API. Your sole purpose is to extract direct and indirect quotes from the provided news article text and return the data strictly as a JSON array. Do not include any conversational filler, introductory text, or markdown formatting (such as ```json) in your response.
For every quote found in the text, create a JSON object following these strict rules: 1. quote_text: The exact quote text. 2. speaker_name: The name or title of the speaker exactly as written in the text. 3. normalized_speaker: Resolve the speaker to their actual full name to ensure database consistency (e.g., resolving 'the Chairman' or 'SecWar' to their actual names). 4. location: The physical location where the statement was made (e.g., 'Pentagon Briefing Room'). If not mentioned, return null. 5. subject_tags: An array of 1 to 3 concise, standardized tags representing the topic (e.g., ['budget', 'force posture']). 6. context: A single, concise sentence summarizing the specific context of the quote.
Required Output Schema: [ { "quote_text": "string", "speaker_name": "string", "normalized_speaker": "string", "location": "string" | null, "subject_tags": ["string"], "context": "string" } ]'
3. Data Processing Scripts:
•	Webhook/Trigger: A function that automatically runs the AI extraction logic and saves the results to the Quotes table, linking the correct story_id, whenever a new story is added to the database.
•	Batch Processor: A standalone background script I can run once to process my backlog of existing stories in small batches (incorporating delays to respect API rate limits) to populate the Quotes table retroactively.
4. API Endpoints:
•	Search Endpoint: An endpoint allowing users to search the Quotes table by Normalized Speaker, Subject Tag, Date Range, or Keyword.
•	Fetch Story Endpoint: A GET /api/stories/:id route that takes a story_id and returns the full archived text, original headline, and publication date directly from the Stories table.
5. Frontend UI Components: Create a search interface for the quotes accessible in the ‘team’ page. Next to each quote in the search results, include a 'View Archived Story' button. When clicked, this button should call the fetch endpoint and display the full, original story text in a clean, scrollable modal window so the user doesn't lose their place on the search page."
